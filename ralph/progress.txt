## Codebase Patterns
- Stack: Next.js 16 (App Router, Turbopack), React 19, TypeScript 7, pnpm. `pnpm typecheck` = `tsc --noEmit`, `pnpm test` = `node --test` (node built-in test runner, no framework).
- `better-sqlite3` is native: it must stay in `serverExternalPackages` in next.config.ts. It must NOT be in
  `pnpm.onlyBuiltDependencies` — v13 ships N-API prebuilds for every platform, and approving the build script makes
  pnpm run node-gyp instead, which fails in any image without python3/make/g++ (removed in US-011).
- `output: 'standalone'` — verify a build with `pnpm build && PORT=xxxx node .next/standalone/server.js`.
- Next rewrites tsconfig.json on build (jsx -> react-jsx, adds .next/dev/types include). Don't fight it; commit the rewritten file.
- DB path comes from env `DATABASE_PATH` (default ./data/review.db); `data/` is gitignored.
- `public/` is served statically by Next (`/embed.js`), but `output: 'standalone'` does NOT copy `public/` or `.next/static` — the Dockerfile (US-011) must copy both, and local standalone smoke tests need `cp -r public .next/standalone/`.
- postMessage protocol between shell and embed.js (contract for US-004/006/007/008):
  - parent -> iframe: `{source:'review', type:'comment-mode', on}` | `{type:'track', pins:[{id,selector,offsetX,offsetY}]}` | `{type:'ping'}` (re-report path)
  - iframe -> parent: `{source:'review-embed', type:'path', path}` | `{type:'click', selector, offsetX, offsetY, viewportWidth, x, y, path}` | `{type:'positions', positions:[{id,x,y}], missing:[id]}`
  - Both sides must check origin. embed.js derives the review origin from its own `document.currentScript.src`.
- To unit-test browser-only files, write them as an IIFE that exports via `module.exports` and returns early when `typeof module === 'object'`; import with `createRequire(import.meta.url)` from the .ts test (avoids TS resolution complaints about untyped .js).
- Server components/routes that call `getDb()` must `export const dynamic = 'force-dynamic'`; otherwise Next prerenders them at build time and opens the DB during the build.
- Next 16 route `params` is a Promise — always `await params`.
- Reviewer display name lives in `localStorage['review:name']`; the preview iframe is `#preview`.
- Browser-testing the iframe bridge: run the dev server with `PREVIEW_OVERRIDE=http://127.0.0.1:3402` and serve a fake
  cross-origin site (`python3 -m http.server 3402`) whose index.html loads `http://localhost:<devport>/embed.js`.
- Shell-side postMessage listeners must filter on both `e.source === frameRef.current?.contentWindow` and `e.origin`;
  Next's dev HMR posts to the same window.
- Shell overlay state that the `message` listener reads must go through a ref (`threadsRef.current = threads` during render); the listener effect only depends on `previewOrigin`, so its closure is created once.
- Navigate the preview iframe imperatively (`frameRef.current.src = ...`), never via a React `src` prop — React skips writing an unchanged prop, so re-selecting a path the iframe already left is a no-op.
- Only the *current* path's pins are tracked by embed.js, so its `missing` list is meaningful for that path alone: replace the outdated set on each `positions` message, never accumulate it.
- Side effects fired from a route handler go out as `void fn().catch(console.error)` so they can never fail the request; any timer they set must be `.unref()`ed or `node --test` hangs.
- Functions that talk to the outside world take the transport as an injectable last arg with a real default (`notify(token, send = sendGrid)`, `selectorFor(el, isUnique)`) — that is how this repo tests without network or DOM.
- Env vars so far: `DATABASE_PATH`, `PREVIEW_OVERRIDE`, `SENDGRID_API_KEY`, `NOTIFY_EMAIL`, `NOTIFY_FROM` (optional), `APP_URL` (optional, for links in emails).
- Admin-style CRUD uses server actions, not API routes: `<form action={fn}>` + `FormData`, logic in `lib/*.ts`, thin `'use server'` wrappers in `app/*/actions.ts`. Errors redirect to `?error=...` (no `useActionState`). `redirect()` throws NEXT_REDIRECT so it must never sit inside a swallowing `try`.
- Next 16 page `searchParams` is a Promise, same as `params` — always await it.
- Docker: multi-stage `node:22-slim` build; runtime stage copies `.next/standalone`, `.next/static` and `public/`, runs as
  the image's `node` user, `CMD ["node","server.js"]` with `HOSTNAME=0.0.0.0`. `mkdir /app/data && chown node:node` before
  `USER node` so the named volume inherits writable ownership.
- The container's node_modules is the pnpm store layout: `require('better-sqlite3')` from `docker exec node -e` fails.
  Use the full `/app/node_modules/.pnpm/better-sqlite3@<ver>/node_modules/better-sqlite3` path for one-off container scripts.
- `docker-compose.yml` uses `expose`, not `ports` — Coolify's Traefik routes to the container; publishing a host port
  would collide on gpu1. To smoke-test locally, curl the container IP from `docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}'`.
- `next dev` auto-generates root `AGENTS.md` (nextjs-agent-rules block) and `CLAUDE.md` (`@AGENTS.md`). They are committed — deleting them just recreates the diff.

- **Learnings for future iterations:**
  - The `pnpm.onlyBuiltDependencies: ["better-sqlite3"]` approval added in US-001 was actively harmful. better-sqlite3 13 has no `install` script but does have a `binding.gyp`, so approving builds makes pnpm fall back to `node-gyp rebuild`; that needs python3/make/g++, which `node:22-slim` lacks. The package ships `prebuilds/linux-x64.node` (N-API) — with the approval removed, install is a plain untar and the module loads fine. Don't add build toolchains to the image to "fix" this.
  - Next's file tracing does copy better-sqlite3's `prebuilds/` into `.next/standalone`, so no manual native-module copying is needed in the Dockerfile.
  - `docker compose exec node -e "require('better-sqlite3')"` cannot resolve the module — standalone output keeps the pnpm `.pnpm/<pkg>@<ver>/node_modules/<pkg>` layout with only next/react/react-dom hoisted. Require the absolute `.pnpm` path.
  - `expose` (not `ports`) matches the redfin-rental-scraper model and how Coolify/Traefik reach the container. Local verification goes through the container IP.
  - `next build` rewrites `next-env.d.ts`; it shows up dirty after any build, same as the tsconfig.json rewrite. Commit it.
